# Hybrid Scheduler

English | [中文](README_zh.md)

Hybrid Scheduler is a FastAPI-based hybrid task-scheduling prototype. It classifies tasks as real-time, short, or batch workloads, orders them with EDF, Round Robin, or SJF, and assigns them across simulated compute nodes in round-robin order.

The current version is intended for coursework, local demonstrations, and scheduling-strategy comparisons. It does not yet launch real containers, Kubernetes jobs, or AWS workloads.

## Features

- `POST /submit` submits CPU or I/O tasks.
- `GET /health` reports service health.
- `GET /metrics` exposes Prometheus metrics.
- Experiment support for RR, SJF, HRRN, EDF, and Hybrid strategies.
- A local Docker Compose monitoring stack with Prometheus and Grafana.

The default Hybrid strategy uses the following mapping:

| Task class | Classification rule | Strategy |
| --- | --- | --- |
| realtime | Deadline is no more than 5 seconds away | EDF |
| short | Estimated duration is no more than 1 second | Round Robin |
| batch | All other tasks | SJF |

## Run Locally

Run the following commands from this directory:

```powershell
Copy-Item .env.example .env
poetry install
poetry run uvicorn hybrid_scheduler.main:app --host 127.0.0.1 --port 8080
```

Once the service starts, the following endpoints are available:

- API documentation: <http://127.0.0.1:8080/docs>
- Health check: <http://127.0.0.1:8080/health>
- Prometheus metrics: <http://127.0.0.1:8080/metrics>

### Enable API-Key Authentication

The service validates an API key only when `API_KEY` is non-empty. It may be left unset for an isolated local demo. Configure a strong random value whenever another machine can reach the service, or place the service behind an identity-aware reverse proxy.

Generate a random value:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Store the result in your private `.env` file:

```dotenv
API_KEY=replace-with-the-generated-random-value
```

Restart the service after changing `.env`. Send the key through the `X-API-Key` header:

```powershell
$headers = @{ "X-API-Key" = "replace-with-your-value" }
$body = @{ category = "CPU"; duration = 0.5 } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8080/submit `
  -Headers $headers -ContentType "application/json" -Body $body
```

Omit `-Headers` when API-key authentication is disabled. A successful response looks like this:

```json
{
  "id": "7fe50f6e-5c90-4603-9fb3-825eaee57e20",
  "status": "queued"
}
```

Task IDs are generated by the server. The request body does not accept an `id` field, which prevents callers from accidentally using names, email addresses, student IDs, or other personal identifiers.

Request fields:

| Field | Required | Description |
| --- | --- | --- |
| `category` | Yes | `CPU` or `IO` |
| `duration` | Yes | Estimated runtime in seconds; must be greater than 0 |
| `deadline` | No | Unix epoch deadline |
| `priority` | No | Lower numbers indicate higher priority; retained by the prototype but not currently used by the default Hybrid strategy |

## Docker Compose

Copy the configuration and set a Grafana administrator password first:

```powershell
Copy-Item .env.example .env
# Edit .env and set at least GRAFANA_ADMIN_PASSWORD; API_KEY is also recommended.
docker build -t hybrid-scheduler:0.1 .
docker compose up -d
```

Local endpoints:

- API: <http://127.0.0.1:8080>
- Prometheus: <http://127.0.0.1:9090>
- Grafana: <http://127.0.0.1:3000>

Compose publishes all ports on `127.0.0.1` only. Grafana anonymous access, account registration, and analytics reporting are disabled. For LAN or public access, place the services behind a controlled reverse proxy with TLS, authentication, and network access controls. Do not simply expose these ports on every interface.

Stop the services with:

```powershell
docker compose down
```

## Run Scheduling Experiments

Run the batch workload with the Hybrid strategy without real-time sleeping:

```powershell
poetry run python -m hybrid_scheduler.experiments.runner `
  --strategy hybrid `
  --workload batch.json `
  --output results/batch_hybrid.csv `
  --dry
```

Accepted `--strategy` values are `rr`, `sjf`, `hrrn`, `edf`, and `hybrid`. Without `--dry`, the runner actually waits for each task's configured `duration`.

The plotting script also requires `pandas` and `matplotlib`, which are not core runtime dependencies:

```powershell
poetry run pip install pandas matplotlib
poetry run python -m hybrid_scheduler.experiments.plot_results `
  --results-dir results `
  --prefix batch_ `
  --output-dir results/plots
```

## Privacy and Security Design

The project applies the following protections by default:

- Project metadata does not contain a personal name or email address.
- `.env`, key files, virtual environments, caches, and newly generated task-level experiment results are excluded from Git and the Docker build context.
- The API does not accept caller-defined task IDs; internal IDs are random UUIDs.
- Scheduler logs record the destination node but not task IDs or task payloads.
- API keys and RabbitMQ URLs use redacted configuration types, so printing the settings object does not reveal their plaintext values.
- AWS credentials are not declared in project configuration. Future AWS integrations should use the standard boto3 credential chain and IAM roles.
- Compose services bind only to localhost, and Grafana disables anonymous access and analytics reporting by default.

Important remaining considerations:

- `API_KEY` is a lightweight safeguard, not a replacement for complete user identity, authorization, rate limiting, or auditing.
- `/metrics` does not expose task IDs, but it does reveal queue length, task categories, and duration distributions. Do not publish it to the internet without access controls.
- The current queue is held in process memory and is lost on restart. The project does not persist API submissions to a database.
- Do not put real names, email addresses, student IDs, customer identifiers, access tokens, or business payloads in task fields, workload JSON, CSV files, logs, or screenshots.
- Adding a file to `.gitignore` does not remove secrets already committed to Git history. Rotate exposed credentials and use a dedicated history-rewriting tool when necessary.

| `PROM_PORT` | `8000` | Reserved standalone Prometheus port setting |
| `GRAFANA_ADMIN_PASSWORD` | None | Required when Compose starts Grafana |

## Current Limitations

- The dispatcher only records simulated assignments; it does not launch remote workloads.
- The background worker uses sequential `sleep` calls and does not represent real parallel scheduling.
- Queue and task state are not persisted.
- User-level authentication, authorization, rate limiting, and complete auditing are not implemented.
- Experiment-level RR approximates task slicing order and is not operating-system-level preemption.
